# MemoryBank: ユーザー好み

> このファイルはDroidが参照するユーザーの好み・スタイルです。
> 質問せずに自動適用します。

---

## コミュニケーションスタイル

| 項目 | 好み |
|------|------|
| 言語 | 日本語（技術用語は英語可） |
| 回答の長さ | 簡潔（冗長な説明は不要） |
| 絵文字 | 使用しない |
| 確認の頻度 | 重要な意思決定のみ確認、軽微な作業は自律実行 |

---

## コーディングスタイル

| 項目 | 好み |
|------|------|
| コミットメッセージ | 英語、Conventional Commits形式 |
| コメント | 最小限（コードで説明できる場合は不要） |
| 変数命名 | camelCase（TypeScript標準） |
| 型定義 | 明示的に記述（inferより explicit） |

---

## 作業スタイル

| 項目 | 好み |
|------|------|
| タスク進行 | 「上から進めてください」= 優先度順に自律実行 |
| 報告タイミング | タスク完了時にまとめて報告 |
| エラー発生時 | 自力で解決を試み、解決不能な場合のみ報告 |
| ドキュメント更新 | 明示的に依頼がない限り更新しない |

---

## 命名の好み

| カテゴリ | 好み | 備考 |
|---------|------|------|
| フレームワーク名 | 製品名を含まない | DiagnoFlow → SprintPath |
| ファイル名 | kebab-case | `user-profile.ts` |
| コンポーネント名 | PascalCase | `UserProfile.tsx` |
| 関数名 | camelCase | `getUserProfile()` |

---

## 技術的な好み

| カテゴリ | 好み |
|---------|------|
| パッケージマネージャー | bun |
| Node.js vs Bun | Bun優先 |
| npm scripts | bun run 形式 |
| テスト実行 | 全テスト通過を確認してからコミット |

---

## 避けるべきこと

- 冗長な説明や繰り返し
- 不要な確認質問
- 絵文字の使用
- 製品名をフレームワーク名に含める
- README/ドキュメントの自動更新（明示的依頼なし）

---

## 優先すること

- 簡潔な回答
- 自律的なタスク実行
- 品質ゲート（test, typecheck, lint）の厳守
- SprintPathの5原則の遵守
